\section{简介}

cindex 是通用的索引制作工具，它的作用类似于 makeindex 和 zhmakeindex，功能和用法也和它们相似。但支持使用 \LUA（\LUAJIT~2.1）进行特殊定制。

输入输出的格式可以由 \texttt{ist} 格式确定，但也支持使用 \LUA 文件文件进行定制。

与 makeindex 一样，cindex 默认的输入/输出格式为 \texttt{idx}/\texttt{ind}。此外，cindex 还支持一种特殊的输入格式 \texttt{ikv}，使用这个格式无需对索引条目进行复杂的转义。同时 \texttt{ikv} 完全兼容 \texttt{idx}，也就是说，{\bfseries 一个合法的 \texttt{idx} 文件就是一个合法的 \texttt{ikv} 文件}。

如果没有显式指定，第一个输入文件的主文件名将用于，确定输出文件和日志文件的主文件名，它们并不继承该输入文件的目录。若未找到某输入文件，且该文件没有扩展名，则会加上 \texttt{.idx} 再次寻找。
目前，cindex 使用 kpsewhich 命令行工具查找相关文件。

不像 zhmakeindex，在没有提供格式文件的情况下，cindex 并\textbf{不}寻找默认的格式文件，而是直接使用程序的默认设置。

cindex 支持多级索引，默认的实现支持至多 5 级，与之相比，makeindex/zhmakeindex 只支持最多 3 级。若使用 \LUA 定制，则层级没有限制，由具体的格式决定。

cindex 只接受 UTF-8 编码的文件，不论是格式文件，亦或是输入输出文件，必须使用 UTF-8 编码。

\begin{description}
  \item[\texttt{-c}] 缩索引项排序项前后的空格。默认情况下，排序项中的空格会被保留。此选项对 \texttt{ikv} 格式的索引无效，默认情况下 \texttt{ikv} 格式总是忽略行首空格，保留行末空格。
  \item[\texttt{-i}] 从标准输入流（stdin）读入索引项。如果使用了该选项，并且没有使用 \texttt{-o} 选项，则排序后的索引将输出到标准输出流（stdout）。
  \item[\texttt{-i} \meta{ind}] 设置输出索引文件为 \meta{ind}。如果没有指定该选项，默认的输出文件名是第一个输入文件 \meta{index_0} 的主文件名加上 \texttt{.ind} 扩展名。
  \item[\texttt{-q}] 静默模式，不向标准错误流（stderr）显示信息。默认情况下处理过程与错误信息会同时在 stderr 与日志文件中输出。
  \item[\texttt{-r}] 禁止隐式页码区间构造，要求页码区间必须使用显式区间符号生成。默认情况下，三个或三个以上连续的页码会自动合并为一个页码区间（如1---5）。
  \item[\texttt{-s} \meta{style}] 设置 \meta{style} 为格式文件。没有默认值。如果没有扩展名，会使用 \texttt{.ist} 作为扩展名。cindex 会首先在当前目录查找格式文件，如果找不到则调用调用 kpsewhich 命令行工具查找，可使用 \texttt{KPSEWHICH_EXE_FILE} 环境变量设置 kpsewhich 二进制文件的位置。
  \item[\texttt{-t} \meta{log}] 设置 \meta{log} 为日志文件。默认情况下，会使用第一个输入文件 \meta{index_0} 的主文件名加上 \texttt{.ilg} 扩展名作为日志文件。
  \item[\texttt{--strict}] 严格区分不同嵌入命令的页码。默认情况下，在页码区间处理时，会将如果页码左区间的嵌入命令与右区间不匹配，会以左区间为准；而如果使用该选项，则要求左右区间的命令类型必须严格匹配。
  \item[\texttt{-z} \meta{sorts}] 设置分组与排序方式为 \meta{sorts}。由 cindex 直接支持的排序方式包括 pinyin/reading，bihua/stroke，bushou/radical。默认值为 pinyin，即中文按拼音分组排序。

  \meta{sorts} 为以西文逗号分隔的列表。默认情况下，cindex 只检查 \meta{sorts} 的第一项，可使用 \LUA 定制。
  \item[\texttt{--kv}] 标记输入文件均为 \texttt{ikv} 格式。cindex 会检查输入文件的扩展名，如果扩展名为 \texttt{ikv}，则将其视为 \texttt{ikv} 格式。
  \item[\texttt{--} \meta{extras}] 输入额外的选项。可由 \LUA 进一步处理。
\end{description}

如
\begin{verbatim}
  cindex -s process.lua index.idx -- some other options
\end{verbatim}
则 \meta{extras} 为表 \textcon{\{ "some", "other", "options" \}}。

\subsection{索引项输入语法}

\texttt{idx} 格式的输入文件，其语法和 makeindex/zhmakeindex 别无二致。该格式下，每行一个索引项，允许空行，但不得跨行。

如下是几个索引项的例子：

\begin{verbatim}
\indexentry{姓名}{15}
\indexentry{ExplSyntaxOn={\verbatim@font !\verb*&!\ExplSyntaxOn&}|hdpindex{usage}}{MMMMI-6}
\end{verbatim}

\texttt{ikv} 格式的输入文件，每个索引项分为“头”和“具体层级”两个部分：

\begin{syntax}
\meta{页码}\meta{分隔符}\meta{Range}\meta{分隔符}\meta{命令}\meta{分隔符}\meta{层级数}
~~~~\meta{排序键_1}
~~~~\meta{显示文本_1}
~~~~\meta{排序键_2}
~~~~\meta{显示文本_2}
~~~~...
\end{syntax}

比如假定使用默认的分隔符 \texttt{,}，上述 \texttt{idx} 格式的输入可改写为
\begin{verbatim}
15,,,1
    姓名
    姓名
MMMMI-6,,hdpindex{usage},1
    ExplSyntaxOn
    \verbatim@font \verb*&\ExplSyntaxOn&
\end{verbatim}

值得注意的是，分隔符前后不能有多余的空格（分隔符本身可以包含空格，可以是多个字符），即便排序键和显示文本相同，也不能省略其中任何一个。排序键行和显示文本行行首的空格可以省略，cindex 默认会忽略行首空格。

\texttt{ikv} 格式完全兼容 \texttt{idx} 格式，只把扩展名改为 \texttt{ikv}，而内容本身不做改变，同样也能被 cindex 正确识别。比起 \texttt{idx} 格式，\texttt{ikv} 无需（也不能）做任何转义。在 \texttt{ikv} 中使用 \texttt{idx} 格式的索引项则除外。

在 \LaTeX 中使用时，索引项输入文件一般是在 \LaTeX 编译过程中自动生成的。


\section{格式文件}

cindex 除了支持 \pkg{makeindex} 的 \texttt{ist} 格式文件外，还支持使用 \LUA 定制。

\subsection{\texttt{ist} 格式文件}

cindex 支持的 \texttt{ist} 格式文件与标准 \pkg{makeindex} 语法完全相同，内容也基本上相同，同时增加了少量控制中文分组输出的格式，它们大多来源于 \pkg{zhmakeindex}。可以在 cindex 中使用标准 \pkg{makeindex} 的格式文件。

格式文件指明了 \texttt{.idx} 输入文件和最终输入文件的格式。该文件在当前工作目录或在
TEXMF 树中由 \pkg{kpathsea} 库查找。一个格式文件由一组 \meta{关键字} \meta{属
性} 的列表组成。\meta{关键字} 分为输出和输出两类。\meta{关键字} \meta{属性} 对可以以任何顺序出现。
以字符 \verb"%" 开头的行是\about{注释}，
\meta{属性} 可以有不同的类型，
\about{字符串}是以任意双引号 \verb|"| 或反引号 \verb|`| 界定的串，
字符是以单引号 \verb|'| 界定的单个\about{字符}，\about{数字}是一个整数。
其中，双引号和单引号界定的串和字符，可以使用反斜线 \verb"\" 符号作为\about{转义符}，以得到
特殊字符或引号本身；而反引号界定的串是表示原始字符串，它不使用转义符。格式文
件中没有指定的项目会使用其默认值。

\subsection{使用\LUA 定制}

使用 \LUA 文件（扩展名为 \texttt{lua} 或 \texttt{cilua}）作为格式文件时，该 \LUA 文件必须返回 \textcon{nil} 或表。cindex 会在合适的时候查询这张表的字段。如果相应字段不存在，cindex 会使用默认值。

\begin{luadoc}{parse_indices_string}
  \begin{luasyntax}
    parse_indices_string: function(
   @  file_path: string|nil,
   @  lines: StrRef,
   @  iv_ikv: boolean
    ) -> function() -> IndexEntryRefMut | table | nil | false;
  \end{luasyntax}
解析传入文件的内容。此函数应当返回一个迭代器函数，每次调用这个迭代器，都会把它的返回值作为一个结构化的索引条目，直到它返回 \textcon{nil}，如果返回 \textcon{false}，相当于忽略该条目。
如果函数返回的是表，其结构见 \luaref[IndexEntryRef]{as_table}，否则，应当返回 \luaref{IndexEntryRefMut}。
\end{luadoc}

\begin{luadoc}{parse_index_line}
  \begin{luasyntax}
    parse_index_line: function(line: StrRef)
   @                -> IndexEntryRefMut | table | false;
  \end{luasyntax}
此函数应当解析某个输入行，返回一个结构化的索引条目，如果返回 \textcon{false}，相当于忽略该条目。
如果函数返回的是表，其结构见 \luaref[IndexEntryRef]{as_table}，否则，应当返回 \luaref{IndexEntryRefMut}。

当它与 \luaref{parse_indices_string} 同时存在时，cindex 只使用 \luaref{parse_indices_string}，因为它覆盖更为广泛。
\end{luadoc}

\begin{luadoc}{empty_indices_callout}
  \begin{luasyntax}
    empty_indices_callout: function(array: IndexEntryArray);
  \end{luasyntax}
当初次解析完后，如果没有任何有效的索引项，则调用此函数。
\end{luadoc}

\begin{luadoc}{page_precedence}
  \begin{luasyntax}
    page_precedence: function | { string, .. } | string;
  \end{luasyntax}
不同种页码的次序。

页码的种类为 \textcon{"Arabic"(n) | "roman"(r) | "Roman"(R) | "alpha"(a) | "Alpha"(A) | "ZhDigits" | "ZhNumber"}，另见 \luaref[IndexEntryRef]{as_table}。
如果是以字符串而非以表给出，则字符串的每一项应为括号内的字符。如 \textcon{\{ "roman", "Arabic", "alpha", "Roman", "Alpha", "ZhDigits", "ZhNumber" \}} 和 \textcon{"rnaRA"} 都表示相同的优先级，这也是默认的优先级。如果是函数，则其返回值必须为表或字符串或 \textcon{nil}。
\end{luadoc}

\begin{luadoc}{group_detect}
  \begin{luasyntax}
    group_detect: function(entry: MergedEntryRef) -> string;
  \end{luasyntax}
判断并返回条目的组别。

cindex 预定义的组别及其排序为 \texttt{nil}，\texttt{Symbols}，\texttt{Numbers}，\texttt{A} \~{} \texttt{Z}，\texttt{BiHua1} \~{} \texttt{BiHua64}（笔画数 1 至 64，超过 64 画的按 64 画计），\texttt{BuShou1} \~{} \texttt{BuShou214}（214 个康熙部首）。
\end{luadoc}

\begin{luadoc}{group_compare}
  \begin{luasyntax}
    group_compare: function(
   @  lhs: string,
   @  rhs: string,
   @  lhs_counts: number,
   @  rhs_counts: number,
    ) -> boolean;
  \end{luasyntax}
组别的排序。如果 \texttt{lhs} 要排在 \texttt{rhs} 前面，则返回 \textcon{true}。目前 cindex 使用的是 \LUA 内置的 \textcon{table.sort} 函数，它是不稳定排序。\texttt{lhs_counts} 和 \texttt{rhs_counts} 分别是对应组别在合并后所拥有的条目数。
\end{luadoc}

\begin{luadoc}{entry_compare}
  \begin{luasyntax}
    entry_compare: function(
   @  lhs: MergedEntryRef,
   @  rhs: MergedEntryRef,
   @  group: string,
    ) -> boolean;
  \end{luasyntax}
条目的排序。如果 \texttt{lhs} 要排在 \texttt{rhs} 前面，则返回 \textcon{true}。目前 cindex 使用的是 \LUA 内置的 \textcon{table.sort} 函数，它是不稳定排序。\texttt{group} 为条目所属的组别。

如果不同组别的排序方式不同，也可使用特化的 \texttt{entry_compare_\meta{group}} 函数，比如 \texttt{entry_compare_Numbers} 如果存在，则对于 \texttt{Numbers} 这个组别，在对其条目排序时，会直接使用这个函数作为比较函数。对于按笔画数和部首的组别，除了会检查 \texttt{entry_compare_BiHua2} 这种外，cindex 还检查不带数字的排序函数：\texttt{entry_compare_BiHua}。 cindex 会优先使用更加具体的比较函数。
\end{luadoc}

\begin{luadoc}{output_style}

  \end{luasyntax}
当使用 \LUA 作为格式文件时，便无法同时使用 \texttt{ist} 格式了。为此，可使用 \texttt{output_style} 表作为替代。这张表的字段就是 \texttt{ist} 中的相应关键字。

\end{luadoc}

\begin{luadoc*}{CIndex.Entry}
# compare_by_default, compare_by_pinyin, compare_by_bihua, compare_by_bushou
! CIndex.Entry.compare_by_default(MergedEntryRef, MergedEntryRef)
!@                               -> boolean;
根据指定的比较算法比较两个条目，如果前者应当排在后者之前，则返回 \textcon{true}。

总体来说，cindex 首先进行忽略大小写的比较，若相等，再区分大小写进行比较，顺序按照 Unicode 的顺序。若汉字与非汉字进行比较，总是非汉字排在前面，而不考虑它们在 Unicode 中的顺序。

使用读音排序时，没有读音数据的字符（包括生僻字）一律排在有读音的字符之前，汉字按其
最常用读音比较，读音相同汉字的按 Unicode 编码排序。

使用笔画数和笔顺排序时，笔画数小的排在前面，笔画数相同的，按横、竖、撇、点（捺）、折的顺序
逐笔画比较，仍然相同的按 Unicode 编码排序；生僻汉字没有笔顺信息的，排在同笔画数有笔顺的字后面。

使用部首和除部首笔画数排序时，部首按康熙字典 214 部首顺序排列，部首和笔画数相同的按
Unicode 编码排序。
\end{luadoc*}

\begin{luadoc*}{}
# find
! Regex.find(self, subject: StrRef, start_pos: number) -> StrRef | nil;
! Regex.find(self, subject: string, start_pos: number) -> string | nil;
从字符串的 \textcon{start_pos} 位置开始，查找匹配该的正则表达式的子串并返回。不论是 \luaref{StrRef} 还是 \textcon{string}，索引均从 0 开始。
\end{luadoc*}

\begin{luarun}{}
-- 可选匹配“字母”，然后是多个数字，然后是具有属性 Script=Han 的字符
local re = Regex([==[\pL?\d+\p{Script=Han}]==]);
print(re:find("999我辈456子"));
print(re:find("999我辈456子", 3));
print(re:find("我456"));
\end{luarun}

\begin{luadoc*}{}
# captures
! Regex.captures(self, subject: StrRef, start_pos: number)
!@              -> nil | { [number] = StrRef, [string] = StrRef, .. };
! Regex.captures(self, subject: string, start_pos: number)
!@              -> nil | { [number] = string, [string] = string, .. };
查找并返回字符串的捕获组。第 0 个索引是匹配的子串。
\end{luadoc*}

\begin{luarun}{}
local function print_value(value)
    if type(value) == "table" then
        print("{");
        for k, v in pairs(value) do
            print(" ", k, "=", v);
        end
        print("}");
    else
        print(value);
    end
end

local re = Regex([==[(\pL)?\d+(\p{Script=Han})]==]);
print_value(re:captures("999我辈456子"));
print_value(re:captures("999我辈456子", 3));
print_value(re:captures("我456"));
\end{luarun}

\begin{luadoc*}{}
# gmatch
! Regex.gmatch(self, subject: StrRef, start_pos: number)
!@  -> function() -> nil | { [number] = StrRef, [string] = StrRef, .. };
! Regex.gmatch(self, subject: string, start_pos: number)
!@  -> function() -> nil | { [number] = string, [string] = string, .. };
返回一个迭代器函数，其返回值依次是匹配的捕获。
\end{luadoc*}

\begin{luadoc*}{}
# gsub
! Regex.gsub(
!@  self,
!@  subject: StrRef | string,
!@  replacement: StrRef | string,
!@  options?: number,
!@  once?: boolean;
! ) -> string, number;
以正则表达式 \textcon{replacement} 替换 \textcon{subject} 中匹配的内容。返回替换后的字符串以及替换次数。
\end{luadoc*}

\begin{luarun}{}
local bit = require("bit");
local re = Regex([==[(\pL)?\d+(\p{Script=Han})]==]);
print(re:gsub("999我辈456子", "[$2,$1]"));
print(re:gsub("999我辈456子", "[$2,$1]", nil, true));
\end{luarun}

\subsection{\textcon{argparse}}

\href{https://github.com/luarocks/argparse/blob/master}{\textcon{argparse}} 是解析命令行的 \LUA 库。
cindex 内置了此库的 \texttt{0.7.2} 版，可使用 \textcon{require("argparse")} 加载。详细用法见 \url{http://argparse.readthedocs.org/}。

cindex 支持在 \LUA 格式中解析命令行中传入的额外的参数，可使用此库解析。

\begin{luarun}{}
local extra_options = { "-o", "cindexout.tex", "cindexin.tex" };
local argparse = require("argparse");
local parser = argparse("mystyle");
parser:argument("input", "Input file.");
parser:option("-o --output", "Output file.", "a.out");
parser:option("-I --include", "Include locations."):count("*");
local args = parser:parse(extra_options);
print(CIndex.Util.table_to_json_string(args));
\end{luarun}
